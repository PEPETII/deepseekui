# Phase 5 工单计划（左侧会话栏一等布局整合）

## 一、阶段目标

把 DeepSeek 网页左侧会话栏纳入“文档化阅读”工作台的视觉与布局体系：扩展启用时，左栏与正文、右侧大纲使用同一套主题令牌、字体和交互反馈；保留 DeepSeek 原生会话导航、折叠、滚动和点击行为；扩展关闭后完整恢复原站。

## 二、本阶段涉及的内容

- 左侧栏探测：继续复用 `data-docshell="side"`，识别 `/a/chat/s/<id>` 会话路由，并为普通 `div` 左栏增加几何/内容密度回退；同时收敛 `aside`/导航回退误命中右侧区域的风险。
- 左侧栏布局：补齐盒模型、滚动边界、字体、间距和响应式规则；不强制覆盖原生宽度，以保留原生折叠状态。
- 左侧栏视觉：米黄、纯白、墨色三主题统一使用 `--dd-*` 令牌，补充链接/按钮的悬停、焦点、当前项状态。
- 现有侧栏搜索：保持注入节点可摘除和本地过滤行为不变。
- 底部原生输入框视觉：仅通过 CSS 统一外层卡片、textarea、占位符、焦点态和发送按钮反馈，不改变原生节点结构、发送链路或定位。
- 版本：行为变更后同步 `manifest.json`、`content.js`、`popup.js`，并修正 popup 可见版本显示。

## 三、本阶段不处理的内容

- 不移动、重建、代理或点击 DeepSeek 原生 textarea、form、发送按钮、会话链接和折叠按钮；原生输入区只允许 CSS 视觉覆盖。
- 不改变侧栏原生数据、排序、会话加载、路由、登录、Token/Cookie、fetch 或私有 API。
- 不新增 host 权限、存储键、消息类型、远程请求或后台下载逻辑。
- 不把左栏内容纳入正文导出/备份正文；打印仍只保留文档纸张，侧栏按现有打印规则隐藏。
- 不引入固定侧栏宽度覆盖；原生展开/折叠宽度和定位由 DeepSeek 保持。

## 四、前置条件

- 已确认当前代码已有 `probeShell/probeSideEl` 和 `data-docshell="side"` 标记链路。
- 已确认 `setOn(false)` 会移除 `.docdeep-injected` 与 `[data-docshell]`，可作为恢复基线。
- 已读取 `docs/known-issues.md` 中 `PAPER-WIDTH-001`、`NATIVE-OUTLINE-001` 相关约束；本阶段不解冻纸宽、不改右侧原生目录只读策略。
- 工作区不是 Git 仓库；以本轮修改前文件哈希和代码走读作为基线，不执行提交、推送或发布。

## 五、代码影响范围（白名单）

- `content.js`：仅调整左栏探测回退与版本号；不改采集、编号、导出、备份和消息协议。
- `content.css`：仅新增/调整 `[data-docshell="side"]` 左栏整合规则、底部原生输入框视觉规则及对应主题/响应式/打印约束；所有规则必须以 `html[data-docdeep="on"]` 开头。
- `manifest.json`：仅同步扩展版本号，不改权限和 host。
- `popup.js`：仅同步诊断版本号及文件头版本注释。
- `popup.html`：仅同步面板可见版本号。
- `docs/功能扩展规划.md`：完成后追加本阶段状态与链接。
- `docs/完成报告/Phase-5-完成报告.md`：完成真实实现和验证后创建，禁止提前建空报告。

## 六、任务拆解

### Task 1 实现（主代理串行）

1. 复核 `probeSideEl` 的左侧几何约束，识别当前 `/a/chat/s/<id>` 路由，并避免无条件使用任意 `<aside>`。
2. 将侧栏根节点、滚动条、文本继承、原生链接/按钮反馈、当前项状态纳入 `--dd-*` 主题令牌。
3. 仅补充不破坏原生宽度/定位的布局规则；小屏不额外隐藏或锁定侧栏状态。
4. 同步版本号，保留 `setOn(false)` 摘除路径。

实机反馈补充：用户截图显示 `0.3.6` 页面左栏没有变化；结合当前 `/a/chat/s/<id>` 地址和左栏非语义容器形态，追加路由识别、几何/内容密度回退，以及仅对已标记左栏注入搜索框的边界修复，版本升至 `0.3.7`。

### Task 2 测试（主代理自测）

- 正常：侧栏命中后具备统一背景、边界、字体、链接/按钮状态和滚动规则。
- 边界：无侧栏/侧栏为右侧区域/侧栏折叠为窄宽度时不抛错、不误标、不强制恢复展开。
- 主题：米黄、纯白、墨色均只通过令牌覆盖，不残留旧主题硬编码侧栏色。
- 关闭：`setOn(false)` 可移除标记和注入搜索框，CSS 规则因根属性消失而失效。
- 非 DeepSeek 页：JS 语法检查和静态夹具不依赖真实站点私有 API。

### Task 3 Review（主代理只读）

检查白名单、规则前缀、版本三处一致、原生交互未被移动/重建、无新权限/存储/消息协议，并记录实机验证限制。

### Task 4 原生输入框视觉补充（主代理串行）

1. 复用现有 `form:has(textarea)` 选择器，只调整表面色、边框、阴影、圆角、文字/占位符和焦点反馈。
2. 发送按钮只调整主题色、悬停、禁用和焦点反馈，不添加事件监听、不改 `type`、不改回车发送行为。
3. 三主题复用 `--dd-*` 令牌，保留打印隐藏和扩展关闭后的原站恢复路径。

## 七、测试计划

- `node --check content.js`
- `node --check popup.js`
- `node --check background.js`
- `manifest.json` JSON 解析与版本一致性检查。
- 静态 CSS 选择器检查：左栏规则全部在 `html[data-docdeep="on"]` 下，主题分支和打印分支可定位。
- 原生输入框静态检查：外层/textarea/发送按钮规则、三主题令牌、焦点/禁用边界和打印隐藏可定位。
- 最小 DOM 夹具走读：命中左 `<aside>`、右 `<aside>`、无 `<aside>`、折叠窄栏和 `setOn(false)` 清理。

## 八、回归测试范围

开关启停恢复原站、字号/主题/右侧大纲开关、侧栏搜索过滤、收藏打开/删除、复制全文、导出 MD/JSON/HTML、打印隐藏侧栏、诊断版本一致、流式正文无重复工具条、虚拟列表滚动无异常。

## 九、完成定义 Definition of Done

- 侧栏在代码层成为一等视觉布局区域，但不改变原生功能节点及宽度/折叠行为。
- 底部原生输入框具备统一卡片、焦点和发送按钮视觉，但不改变原生功能节点及发送行为。
- 三主题、焦点/悬停/当前项、滚动和窄屏规则完成并通过静态检查。
- 关闭扩展的摘除与恢复路径保持有效。
- 白名单 diff 可审查；测试失败或发现误命中时阻断完成并写入报告。
- 长期规划和完成报告基于真实 diff 更新。

## 十、交付与验收条件

- 先完成代码、测试和报告，再向用户汇报。
- 由于当前 Edge DeepSeek 标签已被其他浏览器会话占用，若无法接管，则明确标记“实机视觉未验证”，不把静态通过表述为 UI 已验证。
- 汇报后停止，等待用户验收；未经用户明确确认，不继续扩展到其他页面区域或新阶段。
