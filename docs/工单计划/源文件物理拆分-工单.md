# 重构工单：源文件物理拆分（全部人工维护文件 ≤600 行）

> 纯重构任务：不改对外行为，只改文件物理组织。用户已明确授权修改 AGENTS.md 并放开「禁止直接编辑生成产物」限制。

## 一、目标

消除「构建产物超 600 行」的现状：`content.js`(3722) / `content.css`(1536) / `popup.js`(663) 三个拼接产物全部退役，`content.parts/`、`popup.parts/` 升级为 manifest / popup.html 直接加载的正式源文件。完成后**所有项目文件均 ≤600 行、无生成产物、无豁免**。

## 二、与原计划差异（架构变更声明）

- 原架构：`scripts/build-sources.js` 把 parts 拼接成单文件产物，`@generated` 标记豁免门禁，禁止直接编辑产物。
- 新架构：废弃拼接层，manifest `content_scripts.js/css` 数组与 popup.html `<script>` 按原拼接顺序直接引用 parts 文件。目录名 `content.parts/`、`popup.parts/` 保留（减少 churn，语义由 AGENTS.md 重定义）。
- 等价性依据：Chrome content_scripts js 数组按序注入同一 isolated world，经典脚本共享顶层词法作用域（`function` 声明全局提升、`let/const` 进共享全局词法环境），与拼接进单 IIFE 等价；css 数组按序级联等价。仅两处实质变化：IIFE 壳移除（每文件顶部补 `'use strict';` 保持严格模式语义；popup 本就非严格模式，不加）；符号从函数作用域变为 isolated world 顶层（已核对与 rich-model.js 及扩展内其他脚本无命名冲突）。
- 用户确认：已在会话中明确授权（「修改 AGENTS.md，现在允许直接修改」）。
