# 工单：新增「模板」分区（外观预设 tab）

## 一、任务目标

在 popup 新增「模板」分区（`data-tab="skin"` / `data-pane="skin"`），以具名模板卡的形式承载纸张主题档位。本期只开两张卡：

- **橙色**：映射现有默认外观 `docdeep_theme = 'mi'`（米黄纸面 + 赤陶点睛），即「当前现有的主题外观」。
- **深色**：映射 `docdeep_theme = 'mo'`（墨色深色分支）。

要求：用户点选任一张卡后**即时应用**——当前会话页面换肤 + popup 自身换肤同步完成，无需刷新。每张卡带一枚预览缩略图，直接展示该模板的纸面底色、文字层级与强调色，使「展示外观效果」不依赖切换后才可见。

版本同步 `0.3.22`。

## 二、本次涉及的功能

- 新增「模板」分区：Tab 按钮、pane 卡片、卡片选中态、预览缩略图、点击应用。
- popup 分区数 3（阅读 / 操作 / 收藏）→ 4（阅读 / **模板** / 操作 / 收藏），插入位置紧邻「阅读」，与同为外观类设置聚合。
- 抽出 `applyTheme()` 作为主题应用的**唯一路径**，供模板卡与「阅读」分区的纸张主题下拉共用，消除双入口逻辑漂移。

## 三、本次不涉及的内容

- **主题机制本体**：`content.js` 仍以 `docdeep_theme` 写 `data-doctheme`（`applySettings`/`setOn`）、`content.css` 的 `--dd-*` 令牌三档覆盖，一律不动。模板只是既有主题档位的具名入口，不新增主题、不新增令牌、不新增消息类型。
- **`chrome.storage` 契约**：不新增存储键，模板读写的就是既有 `docdeep_theme`；`DEFAULTS` 八键不变。
- **「阅读」分区的纸张主题下拉**：保留不动。纯白（`bai`）未占用模板位，若删除下拉会造成「纯白」不可达的功能回退（属 breaking change），按兼容方案处理。
- 字号 / 纸张宽度 / 大纲 / 键盘导航 / 隐藏官网目录 / 选区格式工具栏 / 收藏全链路。
- `background.js`、`manifest.json` 权限与 host、`docs/known-issues.md` 历史结论。

## 四、前置条件

- 用户明确提出新增「模板」tab，只展示「橙色」「深色」两项，选中即应用。
- 需求已确认映射关系：「橙色」= 当前现有外观（`mi`），「深色」= 深色主题（`mo`）。

## 六、任务拆解

### Task 1 popup.html：Tab + pane + 样式（已完成）

内容：nav 中「阅读」之后插入 `data-tab="skin"` 的「模板」按钮；`read` pane 之后插入 `data-pane="skin"` 的「外观模板」卡（`card-hd` 标明「选中即生效」），内含 `.skins` 分组与两张 `button.skin[data-skin]` 卡（`橙色 → mi` / `深色 → mo`），每卡由「预览缩略图 + 名称/描述 + 勾选点」三部分组成；末尾补 `pane-note` 说明模板只决定配色、更多档位仍在「阅读」。样式块新增 `.skin*` / `.skin-preview*` / `.sp-*`，插在「底部状态条」之前。

验收：卡片均 `type="button"`、`aria-pressed` 初值 `false`、预览 `aria-hidden="true"`；`data-tab` 与 `data-pane` 顺序一一对应为 `read / skin / act / mark`；预览缩略图**使用固定色**而非 `--dd-*`/`var(--*)` 令牌（否则深色预览在浅色面板中会失真）。

### Task 2 popup.js：模板逻辑与即时应用（已完成）

内容：

- `TEMPLATES`：模板清单（`id / name / desc`），新增模板只需加一项 + 加一张卡。
- `activeTemplate(theme)`：纯函数，命中返回模板 id，未命中（`bai`/空值/脏值）返回 `null`——不误选任何卡。
- `paintTemplates(theme)`：只改 `.skin` 的类名与 `aria-pressed`。
- `applyTheme(value, note)`：**主题应用唯一路径**——校验档位 → 同步 `documentElement.dataset.theme`（深色分支）→ `paintTemplates` → 反向同步 `#theme` 下拉 → 写 `docdeep_theme` → 广播 `DOCDEEP_SETTINGS` → 可选写状态条文案。
- `initTemplates()`：模板卡点击接线，在「任何文档环境」的收尾块中与 `initTabs()`/`initStatusFlash()` 同批调用（便于本地预览夹具验证）。
- `paint()` 末尾追加 `paintTemplates(s.docdeep_theme)`，面板打开时恢复选中态。
- 原「纸张主题」下拉从三元组数组中摘出，改为 `change` 时调用 `applyTheme`。

验收：`node --check` 通过；`activeTemplate` 单测全绿；点卡后 `#theme` 下拉与卡片选中态互相一致。

### Task 3 验证（已完成）

## 七、测试计划

- 正常路径：默认配置（`mi`）打开面板 → 模板分区「橙色」为选中态；点「深色」→ 面板立即转深色 + 「深色」选中 + 「阅读」下拉变「墨色」+ 状态条提示；反向点回「橙色」→ 复原。
- 边界 1（未命中档位）：`docdeep_theme = 'bai'` 时模板分区不选中任何卡，且下拉仍显示「纯白」（不丢档位）。
- 边界 2（空/脏值）：`activeTemplate('')`、`(undefined)`、`(null)`、`('DARK')`、`('__proto__')` 均返回 `null`，不抛异常。
- 边界 3（无 chrome 环境）：`file://` 打开 popup.html（预览夹具）时点击卡片不报错，`applyTheme` 在视觉应用后安全返回。
- 边界 4（存储失败）：`chrome.storage.local.set` 抛错时状态条提示「本地存储已满或写入失败」，卡片选中态保持本次显示、不崩。
