# 工单：新增选区「添加到输入框」浮动按钮

## 一、任务目标

用户在会话正文（回答/提问区）选中文字后，页面浮出一枚扩展自有的「添加到输入框」小按钮；点击后把选中文本插入原生输入框底层 textarea（光标处或追加到末尾），不覆盖已有草稿。富文本表面（Phase-6）开启时同步重渲染表面，保持「表面即所见」。

**明确不做**：不往 DeepSeek 原生选中菜单（隐藏菜单/更多操作/复制/搜索那个弹层）里注入菜单项——那是 React 临时渲染节点，结构随站方构建漂移，且改原生 UI 违反「只打标 + 注入可摘除 UI」原则。按钮是 `docdeep-injected` 自有节点，可摘除。

版本同步 `0.3.31`。

## 二、本次涉及的功能

## 三、本次不涉及的内容

- **不改发送链路**：插入后不自动发送，只落文本；原生 textarea/form/发送按钮归属不变。
- 富文本表面机制本体（`04-rich-editor.js` 的绑定/同步/历史栈）不动，只调用其既有入口 `syncRichFromTextarea / restoreRichSelection`。
- `background.js`、`rich-model.js`、消息总线（无新消息类型，开关走既有 `DOCDEEP_SETTINGS`）、`manifest.json` 权限/host、`docs/known-issues.md` 历史结论。
- 查找高亮、大纲、导出、收藏、键盘导航等既有功能。

## 四、前置条件

## 七、测试计划

- 正常路径：开启功能 → 选中回答里一段文字 → 按钮出现在选区末端附近 → 点击 → 文本落在输入框光标处，富文本表面同步显示。
- 边界 1（追加语义）：输入框已有草稿且光标在末尾 → 插入前自动补空行分段，不与草稿粘连；光标在中间 → 原样插入不加分段。
- 边界 2（非法/空输入）：选区全是空白字符、`text` 为空串、`composeComposerInsert` 传 null/越界索引 → 不插入、不抛异常。
- 边界 3（注入区选区）：在大纲面板、查找栏、格式工具栏、富文本编辑器内部选文字 → 按钮不出现。
- 边界 4（非 DeepSeek 页/未开启）：`docdeep_addtobox=false` 或总闸关闭 → `selectionchange` 不产生按钮；开关重新打开后下一次选区即恢复。
- 边界 5（无 textarea）：输入框未挂载时点击不报错、按钮隐藏。
