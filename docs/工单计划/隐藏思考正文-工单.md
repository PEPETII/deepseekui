# 工单：思考进行中也隐藏思考正文

## 一、任务目标

用户在深度思考阶段不希望阅读 AI 的思考正文：让思考正文在**流式思考期间**不显示，气泡内只保留站点原生的折叠标题行（「正在思考」→「已思考（用时 N 秒）」）与回答正文。版本 `0.3.34` → `0.3.35` → `0.3.36`。

用户已确认两项设计选择（2026-09-15）：
1. 隐藏范围 = **只隐藏思考正文**，保留站点原生折叠标题行；
2. 导出/复制口径 = **保持现状**（导出的 Markdown 仍含思考原文）。

**v0.3.36 验收前修订（2026-09-15，用户反馈）**：用户指出「关闭思考」不应是**直接隐藏**，而应是**收拢**。故把实现从「两态常隐」收窄为「只在思考进行中隐藏正文」，思考结束后本规则自动失效，交还站点原生的收拢态（标题行 + 可点箭头），用户随时能展开回看思考原文。理由：站点在思考期并不提供可用的折叠控件，扩展无法在不点击原生节点的前提下造一个；而回答开始后站点自身即具备完整收拢态，让位即可兼得「不打扰」与「可回看」。

## 二、缺陷/需求根因

- 站点把「思考 / 联网搜索 / 工具」等片段统一放进可折叠区（容器 `.ds-collapsible-text`，`max-height` 过渡由 JS 内联控制，`defaultCollapsed=true`）。标题由 `useCollapsibleAreaTitle` 按片段类型产出：`messageThinking`（中文实为「正在思考」，英文 "Thinking"）、`messageThinkDuration[Plural]`（已思考（用时 N 秒））、`messageThinkStopped`；联网搜索态另用 `messageSearching/deepSearchSearching` 等键。
- 站点行为：思考进行中 → 区域**展开**、标题「正在思考」，思考正文逐字流式可见；回答正文开始输出后 → 标题切换为「已思考（用时 N 秒）」并折叠。用户诉求是让前一阶段也不可见。
- 线上核验（抓 `fe-static.deepseek.com/chat/static/main.3208e09460.css` 与 `main.9199a2404f.js`）：
  - 思考正文容器真实类名 `.ds-think-content`（内含 `.ds-markdown`）。结构：`pw = ({children, icon, isLastFragment}) => <div class={cx(px.GJ,"ds-think-content",isLastFragment&&px.dq)}>{icon}<div class={px.Yv}/>{children}</div>`，即**片段正文行**（icon + 分隔 + 片段 markdown）。
  - `.ds-think-content` 全包仅由 `pw` 渲染、`pw` 仅在 `pS` 内被渲染（2 处 JSX），而 `pS` 只服务 think 片段（`useIsWIPThinking` + `useThinkFragment`）→ **不与联网搜索/工具片段共用**。
  - 标题行由 `useCollapsibleAreaTitle` 独立产出，**不在** `.ds-think-content` 内 → 隐藏正文行不会连带标题行。
  - 站点自身代码用「有 `.ds-think-content` 且无 `.ds-assistant-message-main-content`」判定「思考进行中」（`main.js` 据此决定是否把气泡滚到顶部）→ 该谓词是站点承认的状态划分，扩展沿用它是安全的。
  - 站点**不存在** `ds-thinking` 类名，也**不存在** `data-thinking` 属性（main.js 中计数均为 0）→ 扩展 `THINK_SEL`（`content.parts/00-runtime.js:16`）线上匹配不到节点，`tagThink()`（`01-turns.js`）自引入起从未生效；`isAssistantStructure()` 的 THINK 防护分支同样失效（`Q-INFLATE-001` 现由 `AI_SEL` + 赝文本清理兜住）。该失效链路本工单**不处理**，仅登记。

```css
html[data-docdeep="on"][data-doc-hidethink="on"] .ds-message:has(.ds-think-content):not(:has(.ds-assistant-message-main-content)) .ds-think-content,
html[data-docdeep="on"][data-doc-hidethink="on"] [data-message-id]:has(.ds-think-content):not(:has(.ds-assistant-message-main-content)) .ds-think-content {
```

## 八、测试计划

- 正常路径（v0.3.36）：夹具三态 ——
  1. 「思考中」气泡（有 `.ds-think-content`、无回答正文）→ 开关开时思考正文 `display:none`、标题行仍在、回答区不存在；
  2. 「已思考」气泡（思考正文 + 回答正文并列，模拟站点收拢前的展开态）→ 规则**必须失效**（正文可见），证明控制权已交还站点；
  3. 站点收拢态（`.ds-collapsible-text` 内联 `max-height:0` + 箭头存在）→ 正文被容器裁掉但**未**被本规则 `display:none`，箭头可展开。
- 边界 1：`docdeep_hide_think=false` → 三种气泡的思考正文均可见；扩展关闭（`html` 无 `data-docdeep`）→ 原站显示不变。
- 边界 2：popup 存档为关时开关显示为关；点击开关 → `aria-checked` 翻转且落盘生效。
- 边界 3：`.ds-markdown` 出现在回答正文里不得被误伤（只隐藏思考容器）；非 DeepSeek 页面无该容器时规则不生效。
- 边界 4（已知失效条件，登记不兜底）：若「思考中」气泡内站点已渲染一个空壳 `.ds-assistant-message-main-content`，谓词失配 → 正文重新可见（退化为旧行为，不会崩）。改版观测到该形态时再启用 JS 打标兜底。

## 风险与待实测项

- ~~`.ds-think-content` 疑似通用折叠片段容器，联网搜索片段可能被一并隐藏~~ → **已用证据排除（v0.3.36）**：该 class 全包仅由 `pw` 渲染，`pw` 仅在 `pS`（think 片段渲染器，`useIsWIPThinking` + `useThinkFragment`）内被渲染 2 处，联网搜索/工具片段走的是 `useCollapsibleAreaTitle` 的另一套分支与组件，不共享该容器。
- 新残余（v0.3.36）：思考进行中若站点已渲染折叠箭头（`.ds-collapsible-text-toggle-button` 仅 `isOverflow` 时出现），此时点它**无法展开**——正文正被本规则隐藏。回答开始输出后规则失效、箭头恢复可用。若实测观感不佳，可再追加一条「思考期隐藏该箭头」的规则（代价：可能连带隐藏同期联网搜索折叠区的箭头），属可选收尾项，未在本工单实施。
