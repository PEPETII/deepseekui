# 思考自动收拢-工单（v0.3.38）

## 一、背景与现象

用户报告：AI 回答结束 / 回答正文开始显示后，思考过程仍保持展开（旧图1）；预期仅保留「已思考（用时 N 秒）」标题行与右侧箭头，思考正文自动折叠，且用户此后手动展开不得被再次强制收起。

## 二、根因（线上 bundle 实证，非假设）

核验对象：`fe-static.deepseek.com/chat/static/main.9199a2404f.js`（与 `main.3208e09460.css`，2026-09-15 抓取，与 0.3.37 审计同 hash，未换版）。

1. **站点不会自行收拢**。可折叠组容器 `mi`：`[l,d]=(0,ep.useState)(!0)` —— `isShowDetail` 初始**展开**，全文检索该组件仅有标题行 `onToggle` 一处翻转（`d(e=>!e)`），**不存在**任何「回答正文出现后自动 `d(false)`」的 effect。`known-issues.md` 旧行 211「回答正文开始输出后切『已思考』并折叠」结论有误，已按追加原则在新条目更正。
2. **扩展侧时间窗让位后无人接管**。`01-reading.css` v0.3.36 规则只在「气泡有 `.ds-think-content` 且无 `.ds-assistant-message-main-content`」时隐藏思考正文；回答正文一挂载规则失效，预期站点接管收拢——而站点不收拢（见 1），思考正文就此长驻展开。
3. **结构事实**（与本次实现直接相关）：
   - THINK 片段经 `pS`/`pw` 渲染为裸 `.ds-think-content`，**不经** `.ds-collapsible-text`（`gC` 只包超长回答正文，`collapsedHeight:192`）。
   - 组容器内联样式含 `--collapsible-area-title-height:34px`（站点粘性标题用），可作运行时锚点；子顺序 = 标题行（`pj`，含 `onClick=onToggle`）→ topRef → 片段列表。
   - 折叠时站点把片段**整体卸载**（`(l?i:[]).map`），故「`.ds-think-content` 仍挂载」⇔ 组处于展开态。
   - 标题行元素跨折叠/展开**持久存在**（仅 className 变化），适合做 WeakSet 防重入锚点。

## 三、目标

回答正文挂载后，对原生标题行转发一次 click，完全复用站点折叠状态机 / 动画 / 埋点；每条回答只代点一次；用户真实点击后永久接管；虚拟列表重挂后维持收拢；不碰搜索/工具片段与用户消息；`docdeep_hide_think=false` 时完全不干预。

## 四、方案（状态转换）

```
思考中（有 .ds-think-content，无 main-content）→ 不干预（维持 v0.3.36 CSS 时间窗策略）
回答正文挂载 + 思考片段仍挂载 → 代点一次原生标题行 → 站点自身翻转 isShowDetail、卸载片段
用户真实点击标题行（isTrusted）→ thinkCollapseState 记 'user' → 之后永不代点（含重挂）
虚拟列表重挂（新元素、同 message-id）→ attempts<3 允许再次代点，维持收拢
结构不匹配（找不到标题行锚点）→ 按 key 计数，3 次后止损，避免 classify 每轮空转
```

防重入三重保险：`thinkClickEls`（WeakSet，同一标题行元素只点一次）、`thinkCollapseState`（key → attempts≤3 / 'user'）、`docdeep_hide_think` 门控。

## 六、风险与边界

- 代点的是站点自己的标题行，事件路径与用户真实点击完全一致（React 委托 + `stopPropagation`）；`isTrusted=false` 不会触发扩展自身的接管监听。
- 若站点改版（换内联锚点变量 / 标题行不再首位），`thinkTitleRowOf` 返回 null → 3 次止损，退化为现状（不收拢），无副作用。
- `THINK_SEL` / `tagThink` 死链路（THINK-SEL-001）与本功能无交集：`tagThink` 因 `.ds-thinking` 不存在从未生效，不会注入第二套按钮；本功能亦不依赖它。清理仍按原计划另开工单。
