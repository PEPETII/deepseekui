# 删除工单：移除自动备份 + 历史时间线 + 全局搜索

## 一、删除目标

删除“备份功能”全链路：`content.js` 自动备份生产端（`maybeBackup`/`pruneHistoryList`/60s 节拍/心跳钩子/快照 `backup` 字段/备份设置键）+ `popup.html/js` 备份设置 UI（开关/间隔/条数）、历史时间线 UI 与逻辑（`#history-list` 打开/删除/导出单条）、诊断备份行与报告 backup 字段。因全局搜索的索引数据源为“书签 + 历史快照”，备份删除后其历史分支失去意义，按用户确认连带删除全局搜索全链路（`#global-search/#global-results`、索引纯函数、诊断/预热接线）。旧用户本地的 `docdeep_history_v1` 及三个备份设置键在 popup `load()` 中主动 `remove` 清理，释放配额。

## 二、本次删除涉及的功能

- 功能 4（自动备份 + 会话历史时间线）：整功能删除，含生产端、消费端、存储键、设置键、诊断/报告字段。
- 功能 6（跨会话全局搜索 MVP）：整功能删除。原因：其 `buildGlobalIndex` 联合索引的历史分支依赖功能 4 的快照；备份删除后只剩书签源，与收藏区自带搜索框重复，无保留价值。经用户明确确认连带删除。
- 功能 3/5/9/10：不碰。`buildBookmarksExport` 的 settings 段随备份键同步缩为 6 键（老文件无该段仍可导入，导入只读 bookmarks 段，不受影响）。

## 三、本次不删除的内容

- `background.js` 的 `html` mime 分支（属功能 3-HTML，与备份无关）。
- `content.js` 的 `collectVisibleTurns`（导出采集仍用）、`buildMarkdown`/`exportConversation`/`DOCDEEP_EXPORT` 路由、`heartbeat`/心跳快照本体。
- 收藏管理全链路（`docdeep_bookmarks`/`docdeep_schema_ver`/导入导出/搜索筛选/改名）。
- `PAPER-WIDTH-001` 冻结区、`classify/mergeQuestionOrder/alignNativeWithRegistry/collectAllTurns/scrollToStoredQuestion` 算法本体。
- 不新增 host 权限/远程 fetch；`docs/known-issues.md` 结论不改写。
