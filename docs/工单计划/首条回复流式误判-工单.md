# 工单：修复新会话首条回复流式阶段的提问误判（Q 编号污染）

> 状态：**已立项，未执行**。本文档只做计划，不包含任何实现改动。

## 一、任务目标

修复如下缺陷（2026-09 用户反馈，附三张截图证据）：

- 图 1：新会话首次提问后，**AI 回答**的卡片上被打上 `Q3 · 我的提问` 标签（应为仅用户消息持有该标签）。
- 图 2：右侧大纲同时被污染，出现 `Q2 · 已思考（用时 3 秒）`、`Q3 · 正在搜索正在搜索…`、`Q4 · 正在搜索正在搜索…` 等条目——全是 AI 回复的中间过程，不是用户提问。
- 图 3：刷新浏览器后一切恢复正常（最终态 DOM 一次判对）。

目标：新会话首条回复的**思考/搜索流式阶段**不再被 `classify` 判为用户提问；已被污染的会话内状态能在后续 `classify` 轮次中**自愈摘除**，无需刷新；`qOrder/qInfo` 不残留赝 Q key。版本同步 bump（当前 `0.3.31`，预计 `0.3.32`，以执行时三处现状为准）。

## 二、缺陷根因（诊断结论，代码为证）

**根因 A —— 结构判定盲区（误判源头）**：`content.parts/01-turns.js:33-41` 的 `isAssistantStructure` 只认 `AI_SEL`（`.ds-markdown.ds-assistant-message-main-content` 等）与 `THINK_SEL`（`.ds-thinking` 类 / `[data-thinking]`）。新会话**首条**回复的搜索/思考阶段容器两者皆无，但有可见文本（"已思考（用时 3 秒）"、"正在搜索…"），`isUserTurn`（01-turns.js:76-79）兜底"非助手结构且有文本即用户"成立 → 误判为 `user`。

**根因 B —— 流式哈希 key 滚雪球**：误判元素无 `data-message-id` 可用时走 `u: + hashText(text)`（`keyForTurnEl`，01-turns.js:127-132），流式文本逐轮变长 → 每 tick 生成新 key 入 `qOrder`，同一助手轮次滚出 Q2/Q3/Q4 多个条目（`Q-INFLATE-001` 同族，载体从"正在思考"换成"已思考/正在搜索"）。

**根因 C —— 自愈机制覆盖不全（污染残留）**：

1. `isBogusQuestionText`（01-turns.js:44-53）只匹配 `正在思考` 双写 / `思考过程(已折叠` / `Thinking` 双写，**不匹配"已思考（用时 N 秒）"与"正在搜索"**，`pruneBogusQuestions` 摘不掉。
2. 角色翻转自愈依赖 `classify` 重新枚举到同一元素（12-navigation.js:295-313 `changedRole → resetTurn`）；但流式过程中 React 会重构/嵌套消息 DOM，`queryTurns`（01-turns.js:20-28）只返回最外层 turn，已带 `data-docrole="user"` 与注入标签的内层元素从此不再被遍历 → 永不翻案。`qOrder/qInfo` 仅在 URL 切换时清空（12-navigation.js:274-286），会话内长期残留。

**为何刷新即正常**：最终态 DOM 中 `AI_SEL`/`THINK_SEL` 均已存在，`isAssistantStructure` 一次判对，且不存在流式中间形态。**为何只在首条出现**：新会话首条回复的流式容器结构与后续轮次不同（无既有消息骨架可复用），后续轮次一上来即有可识别的助手结构。
