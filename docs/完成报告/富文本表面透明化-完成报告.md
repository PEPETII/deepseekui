# 富文本表面透明化完成报告（修复原生悬浮提示被表面遮挡）

## 一、阶段目标回顾

用户报告：DeepSeek 原生输入框自带的悬浮提示（DOM 浮层）会被本扩展不透明的 `#docdeep-rich-editor` 富文本编辑表面整块盖住。任务：按方案 A 修复——表面背景改透明，可见底色还给底层 textarea；同轮评估的「原生选中菜单盖住『添加到输入框』按钮」问题确认属浏览器 UI 硬限制，用户决定暂不修改。

## 二、已完成任务

1. `02-composer-rich.css`：`textarea[data-docdeep-rich-source="1"]` 规则移除 `background: transparent !important`，textarea 恢复自绘背景（沿用既有 `--dd-surface-2` / hover / focus 令牌规则）。
2. `02-composer-rich.css`：`#docdeep-rich-editor` 背景由 `var(--dd-surface-2)` 改为 `transparent`，表面只承载文字、光标与占位符；两处补注释说明约束（表面 z-index 恒高于一切站点浮层，必须透明才能让下层提示透出）。
3. 版本号四处同步 `0.3.31` → `0.3.32`（`manifest.json` / `content.parts/00-runtime.js:VERSION` / `popup.parts/00-core.js:POPUP_VER` / `popup.html` 徽标）。
4. 文档：`docs/功能扩展规划.md` 追加 v0.3.32 条目；本报告。

## 三、实际修改内容

纯 CSS 行为修改，无 JS 逻辑改动、无新增存储键/消息类型/权限。根因：表面以 `position: fixed; z-index: 2147483000` 不透明覆盖输入框区域，任何低于该层级的站点原生 DOM 浮层都被遮挡。而富文本表面在线时原生 textarea 的文字、光标、placeholder 已全部透明化，表面自身的不透明背景并非功能必需，因此背景职责移回 textarea 即可，无需与站点 tooltip 的 z-index 竞争。

## 六、关键实现说明

- 背景职责移交后，输入框观感由既有规则保障：`body form:has(textarea) textarea` 的 `background: var(--dd-surface-2)`、圆角、hover/focus 底色全部照旧生效；表面 `padding` 9px/17px 的文字对齐补偿不变，文字起点仍与原生输入框对齐。
- 视觉差异点：表面此前自身带背景且两侧内收 5px，内收缝隙露出 form 底色；现在 textarea 背景通铺到自身全宽，两侧 5px 缝隙同色，输入框观感与非富文本模式一致。
- 已知不可达状态不受影响：富文本源 textarea `pointer-events: none` + `tabIndex=-1`，其 `:hover`/`:focus` 底色在富文本模式下原本就被表面挡住不可见，透明化后依然不可达，无新增视觉回归。
- 墨色主题无需另改：textarea 背景走 `--dd-*` 令牌，`[data-doctheme="mo"]` 分支自动适配。
- `setOn(false)` / `removeRichEditor()` 摘除表面并移除 `data-docdeep-rich-source` 后，textarea 回到原生样式路径，可摘除原则不受影响。
