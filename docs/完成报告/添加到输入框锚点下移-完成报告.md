# 添加到输入框锚点下移完成报告（缓解原生选中菜单遮挡）

## 一、阶段目标回顾

用户报告：会话正文选中文字后浮出的「添加到输入框」按钮会被 Edge 浏览器原生选中菜单（隐藏菜单/复制/搜索）覆盖。该菜单属浏览器 UI，绘制在所有网页内容之上，z-index 无法竞争，无 API 查询其位置——根治不存在。任务：按已确认的缓解方案把按钮锚点换到选区末行下方，降低与原生菜单的重叠概率。

## 二、已完成任务

1. `content.parts/07-addtobox.js`：定位逻辑抽为纯函数 `addBoxAnchorPosition(anchor, btn, viewportWidth, viewportHeight)`——默认 `top = anchor.bottom + 6`（末行下方），下方放不下才回落 `anchor.top - 高 - 6`（上方），左右钳回视口（贴边 8px）；`positionAddToBox` 改为调用该函数。
2. `tests/addtobox.test.js`：新增 `addBoxAnchorPosition` 6 例单测（下方优先 / 上方回落 / 两头放不下钳顶 / 右端越界 / 按钮过宽 / null 兜底），沿用源码提取纯函数的做法。
3. 版本号四处同步 `0.3.32` → `0.3.33`。
4. 文档：`docs/功能扩展规划.md` 追加 v0.3.33 条目；本报告。

## 三、实际修改内容

行为调整而非缺陷修复：原逻辑 `top = anchor.top - 高 - 6`（末行上方）、`top < 8` 才落下方；新逻辑反转优先级——下方优先、上方兜底。左右方向不变（末行右端 +6，越界左移）。选择依据：Edge 原生选中菜单锚定选区起始端附近（首行上方），末行右下方与之重叠概率最低。选区跨多行时末行矩形远离菜单锚点，效果最明显。

## 六、关键实现说明

- 纯函数输入为普通矩形对象 `{top, bottom, right}` 与 `{width, height}`，不依赖 DOM，可在 Node 单测覆盖全部边界。
- `null`/非数值输入兜底为 0 参与运算，最终被贴边钳制成安全值，不抛错。
- 视口高度不足（选区贴底）时回落上方——该场景原生菜单若同时锚在上方可能仍重叠，属已知残留概率，见第十一节。
