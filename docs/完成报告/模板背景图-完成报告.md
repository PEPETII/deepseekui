# 模板背景图完成报告

## 一、阶段目标回顾

在 popup【模板】分区增加背景图开关、PNG/JPG 本地上传、预览、删除和可分享模板包导入/导出；背景图与模板配置关联并保存到 `chrome.storage.local`，不增加远程服务、权限或第三方依赖。

## 二、已完成任务

- 增加“开启背景图”开关，显示“已开启/已关闭”，默认开启以保持已有内置背景行为。
- 增加推荐尺寸、16:9、JPG/JPEG、PNG 和 5 MB 限制说明。
- 增加上传、重新上传、删除、读取中状态、成功/失败提示和实时预览。
- 增加模板 JSON 导入/导出，背景图以 data URL 内嵌，可作为文件分享后再导入。
- 关闭背景时移除页面背景节点；删除自定义图时回退已有内置 PNG。
- 保留既有收藏导出结构，并在其 `settings` 中携带背景配置。

- `popup.parts/00-core.js`：新增 `docdeep_template_background` 默认值、5 MB 和 data URL 限制、背景配置规范化；收藏导出携带背景配置。

## 四、数据模型

新增本地键 `docdeep_template_background`：

```json
{
  "enabled": true,
  "dataUrl": "",
  "mimeType": "",
  "name": "",
  "size": 0,
  "width": 0,
  "height": 0
}
```

缺失键回退为默认开启和内置背景；关闭只改变 `enabled`，不会删除已上传 data URL；删除操作才清除自定义图片字段。

## 五、模板包格式

导出包使用 `app=docdeep`、`kind=template`、`version=1`，结构为 `template.id/theme/background`。导入时校验包类型、版本、主题白名单、背景配置类型、PNG/JPEG data URL 和 5 MB 对应长度上限；不写入对话正文、账号或 Token。

## 六、交互实现

- 开关使用 `role="switch"`、`aria-checked` 和独立状态文字，适合键盘及辅助技术识别。
- 图片读取阶段按钮组进入 `aria-busy=true`，上传、删除和模板包操作暂时禁用。
- 自定义图成功解析后自动开启并显示文件名、尺寸和大小；关闭时显示站点默认背景提示；开启且无自定义图时预览内置 1920×1080 PNG。
- 页面仍通过既有 `DOCDEEP_SETTINGS`、`classify()` 和 `setOn(false)` 清理链即时同步。

## 九、已确认结论

- 新设置键有 popup/content 双端默认值，旧用户缺少该键时不会报错，默认继续使用内置背景。
- 不支持的 GIF、空文件、超过 5 MB 文件、无效 JSON、错误模板版本和超大/非法 data URL 均有明确失败结果，旧配置不被覆盖。
- 自定义背景仅通过本地 storage 和用户主动导出的 JSON 文件流转；manifest 权限和 host 未扩大。
- 页面背景仍使用固定 `cover`、居中、不平铺、鼠标穿透和既有打印隐藏规则。

## 十一、与原计划的差异

- 原模板专题只承载主题档位；本次按用户新需求增加本地背景对象、上传预览和模板包导入/导出。
- 因现有项目没有独立模板分享服务，采用可分享的自包含 JSON 文件；没有新增在线分享 API、远程上传或账号同步。
- 保留现有单一橙色模板卡，不把背景图伪装成第二个主题模板。

## 十二、风险与兼容

- Base64 会使图片体积膨胀，5 MB 文件可能接近 storage 配额；写入失败时提示用户且旧配置保持不变。
- 关闭背景不会删除自定义图，重新开启仍可恢复；删除后只回退到内置默认 PNG。
- 当前工作区已有其它未提交的主题、富文本和背景相关差异；本报告只覆盖模板背景需求，不回滚或合并其它改动。
