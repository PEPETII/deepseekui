## 六、关键实现说明

- **模板不是新主题，是既有档位的具名入口**：`橙色 → mi`、`深色 → mo`，落盘键仍是既有 `docdeep_theme`，不新增存储键、不新增消息类型、`DEFAULTS` 八键不变、`content.css` 令牌零改。因此本次改动完全落在 popup 两层，内容脚本侧零风险。
- **两个入口共用一条应用路径**：抽出 `applyTheme()` 后，「阅读」的纸张主题下拉与模板卡调用同一函数，写入顺序（面板换肤 → 选中态 → 下拉 → 落盘 → 广播）完全一致，不会出现「从模板切过去有效、从下拉切过去偶尔不生效」这类漂移。
- **选中态与档位解耦**：`activeTemplate()` 对 `bai`/空值/脏值一律返回 `null`，所以用户若在「阅读」里选了**纯白**，模板分区不高亮任何卡（而不是错误高亮「橙色」）——避免把「当前外观」说成与事实不符。同理，`applyTheme` 的档位白名单额外放行 `bai`，保证下拉仍能切到纯白，这是刻意的功能保留而非遗漏。
- **为什么没删「阅读」里的纸张主题下拉**：纯白档位未占用模板位，删掉下拉会让「纯白」不可达，属 breaking change；按 AGENTS.md「breaking change 须先声明并获用户确认」，本期按兼容方案保留，两个入口以代码级同步保持一致。
- **预览缩略图刻意硬编码颜色**：缩略图的职责是「在任何面板主题下都如实展示该模板的样子」，若用 `var(--*)` 令牌，深色预览会在浅色面板里被染成浅色，失去展示意义。这是本文件里唯一允许硬编码颜色的位置（静态校验脚本已把这条约束固化为断言）。
- **面板内不引入新令牌**：卡片外壳全部复用 popup 既有令牌（`--surface/--line/--hover-tint/--brand/--brand-weak/--btn-primary-text`），因此米色与深色两个分支都自动成立，无需给模板卡另写 `[data-theme]` 分支。
