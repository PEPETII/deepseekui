## 一、工单

## 二、变更摘要

新增一条**带时间窗**的 CSS 规则：仅当气泡处于「思考进行中」（有 `.ds-think-content` 且**无** `.ds-assistant-message-main-content`）时隐藏思考正文行 `.ds-think-content`，气泡内只剩站点原生的标题行（「正在思考」）；回答正文一开始输出，规则立即失效，由站点自身的收拢态接管（「已思考（用时 N 秒）」+ 可点箭头），用户点开即可回看思考原文。该行为由 popup「辅助功能 → 隐藏思考过程」（存储键 `docdeep_hide_think`，默认开）控制，关闭或停用扩展即恢复原站显示。

与 v0.3.35 的关键差别：v0.3.35 是**两态常隐**，导致站点自己的折叠箭头点开也无内容（用户反馈的「直接隐藏」）；v0.3.36 改为**收拢**——隐藏只覆盖思考进行中这一段，折叠控制权随后交还站点，箭头恢复可用。

## 四、与原计划差异

1. 初版工单只有「CSS 常隐」；用户中途要求做成 popup 开关 → 追加开关链路与 UI 两个 Task（白名单文件集合不变）。
2. **v0.3.36 二次收窄**：用户验收前指出「关闭思考」应表现为**收拢**而非**直接隐藏** → Task 1 规则由「无时间窗常隐」改为「仅思考进行中隐藏」，版本由 `0.3.35` 顺延 `0.3.36`。
3. `docdeep_hide_think` 默认取 **开**，偏离「新功能默认关或最保守档」惯例：用户明确要求该显示行为生效，默认关则功能不可见；开关仅提供关闭能力。改为默认关只需改两处 `DEFAULTS`。
4. **并行改动导致的版本位归属（非本次所为，已核对无冲突）**：本次修订落盘时版本为 `0.3.36`；随后并行的「Enter 发送转发」改动（`docs/工单计划/Enter发送转发-工单.md`，方案 B，`0.3.36 → 0.3.37`）以本版本为基线把四处版本位推进到 `0.3.37`。故**当前仓版本为 `0.3.37`**，本次改动在 0.3.37 中完整保留。已逐项核对本次 11 个触点（CSS 收拢规则、`HIDE_THINK_ATTR`、`applyHideThink` 定义与调用、两处 `DEFAULTS`、`13-entry.js` 监听、`popup.html` 开关行与文案、`02-themes.js` paint、`03-entry.js` 接线）均未被覆盖，未产生冲突。

## 七、发现的问题

1. **`.ds-think-content` 不与联网搜索/工具片段共用**（v0.3.35 工单曾列为风险，本次用证据排除）：该 class 全包仅由 `pw` 组件渲染，而 `pw` 仅在 `pS` 内被渲染 2 处，`pS` 只服务 think 片段（`useIsWIPThinking` + `useThinkFragment`）；联网搜索/工具走 `useCollapsibleAreaTitle` 的另一套分支。原风险条目已在工单中划除。
   同时确认：**折叠容器 `.ds-collapsible-text` 只包内容**（站点 `gp` 的 `children` 只有 content，`max-height`/`height` 都设在这层），**标题行与箭头在其外部**由父组件渲染 —— 这正是「站点收拢后仍能看到『已思考（用时 N 秒）』一行」的结构前提。
2. **`THINK_SEL` 自引入起在线上从未生效**（非本次改动引入）：线上核验显示站点不存在 `ds-thinking` 类名与 `data-thinking` 属性，真实类名为 `.ds-think-content`。`tagThink()` 注入的「思考过程(已折叠,点击展开)」按钮、`.ds-thinking-inner` 两行截断、`doc-think-collapsed`、`data-doc-think-done` 均为死代码，`isAssistantStructure()` 的 THINK 防护分支同样失效（`Q-INFLATE-001` 现由 `AI_SEL` + 赝文本清理兜住）。本次未清理（删除属破坏性改动，需另开工单）。
3. **v0.3.35 的 UX 缺陷（用户反馈）**：常隐把站点折叠箭头变成死控件。已由本次时间窗方案修复，并在夹具中对 v0.3.35 对照完成复现取证。
4. 已知残余：思考**进行中**若站点已渲染箭头，此时点它仍无法展开（该窗口内正文正被本规则隐藏）；回答开始后恢复正常。属有界残余，已登记工单。
5. 工具链缺陷（影响验证，不影响产品）：同文件并行编辑曾静默丢写（已改串行 + 复核）；popup 夹具假 `chrome` 必须注入在 parts 脚本**之前**；夹具中受父级 `max-height` 裁剪的元素必须用**父容器** `offsetHeight` 度量（子元素自身高不受裁剪影响）；夹具页若内嵌交互探针，截图会拍到探针点击**之后**的状态，故探针页与截图页必须分开生成。以上均已写入技能与记忆。

## 九、影响面评估

- 仅视觉层 + 一个新设置键；不改消息协议、不改存储结构、不改导出/复制/查找文本口径。
- 老用户存量配置：`applySettings` / `load` 均为 `{...DEFAULTS, ...stored}` 合并，无该键时落到默认开；`setOn(false)` 与开关关闭均移除属性，原站可完整恢复。
- 时间窗判定为纯 CSS，无新增 JS 轮询 / 监听 / MutationObserver，流式期间零额外开销。
- 兼容性：`:has()` 需 Chrome 105+，`manifest.json` 的 `minimum_chrome_version` 为 `109`，满足。
