# 界面配色覆盖审计（针对 v0.3.21）

- 审计日期：2026-09-11
- 审计对象：`content.css` / `content.js` / `popup.html` / `popup.js`
- 审计目标：找出扩展未改变颜色、或颜色适配不完整的位置，逐条列出
- 是否改代码：**否**（本文件为只读审计结论，未修改任何实现文件）
- 编号规则：`COL-xxx`，便于与人工排查结果逐条对照

## 一、审计方法与证据等级

| 等级 | 含义 |
| --- | --- |
| 【实证-A】 | 无头浏览器加载扩展后的真实渲染截图 |
| 【实证-B】 | 站点线上 CSS（`fe-static.deepseek.com/chat/static/main.5b40800003.css`，285 KB）中该选择器/令牌的原文 |
| 【实证-C】 | 真实渲染 DOM 中该类名确实出现（登录页 / 公开分享页） |
| 【推断】 | 依据选择器与站点 CSS 推导，需登录态实测确认 |

审计手段：

1. `curl` 站点主样式表，统计出 **455 个 `ds-*` 语义类名、75 个 `--dsw-alias-*`、12 个 `--dsw-specific-*`、253 个组件级 `--dsl-*` 令牌**，并提取站点调色板原始值。
2. Edge headless 加载扩展，对 `chat.deepseek.com/`（登录页）与 `chat.deepseek.com/share/<id>`（公开会话页）分别截图，并 `--dump-dom` 取真实 DOM 类名。
3. 对 `content.css` 做关键词命中统计，确认哪些站点组件是 0 规则。

关键基线数据（站点原始色）：

- 站点浅色：底 `#fff`（`--dsw-alias-bg-base` = bluish-00），正文 `#0f1115`，品牌蓝 `#3964fe`（deepseek-500）
- 站点深色：底 `#151517`（bluish-950），层2 `#2c2c2e`，层3 `#353638`，正文 `#f9fafb`，品牌蓝 `#5686fe`
- 主题开关机制：JS 在 `<body>` 上写 `class="zh_CN dark" data-ds-dark-theme="dark"`，并在 `body[data-ds-dark-theme]` 里覆盖 **75 个** `--dsw-alias-*` 令牌

扩展基线数据：`--dd-surface #F1EFE8`／`--dd-text #2D2A26`／`--dd-brand #C06B52`（赤陶）；`content.css` 中 `dsw-alias` 命中 **0** 次。

## 二、机制层遗漏（影响面最大）

| 编号 | 位置 | 问题描述 | 等级 |
| --- | --- | --- | --- |
| COL-001 | 全局主题识别 | 扩展**完全不识别站点自身深浅模式**。`content.js` 全库无 `dark`／`prefers-color-scheme`／`data-ds-dark-theme` 任何引用（grep 命中 0），只写自己的 `data-doctheme`。站点处于深色时，凡扩展未显式覆盖的区域保持深色 → 同屏深浅混搭。登录页截图实证：页面被刷成米黄 `#F8F7F4`，但手机号/验证码输入框、微信二维码卡仍是深色，协议说明文字是站点浅灰（在米黄底上几乎不可读）。 | 实证-A |
| COL-002 | 色板体系 | 扩展自建 `--dd-*` 一套色，**不引用站点令牌**（`--dsw-alias-*`/`--dsw-specific-*`/`--dsl-*` 命中 0）。同一语义两套色：站点品牌蓝 `#3964fe` vs 扩展赤陶 `#C06B52`；站点浅底纯白 `#fff` vs 扩展米黄 `#F1EFE8`。凡是落到未覆盖区的元素，一律回到「冷白＋蓝＋中性灰」，与纸感暖调并排。 | 实证-B |
| COL-003 | `color-scheme` | 扩展自绘浅色表面却**未声明 `color-scheme: light`**（`content.css` 命中 0）。站点在 `@media (prefers-color-scheme:dark){page{…color-scheme:dark}}` 里把文档声明为深色，于是浏览器原生控件（滚动条、`textarea` 右下角拖拽手柄、日期/下拉弹层、原生 focus 环）仍按深色绘制。 | 实证-B |
| COL-004 | `:-webkit-autofill` | 未处理自动填充（命中 0）。登录框/输入框自动填充后出现浏览器默认浅黄底＋深字，与主题无关地打补丁。 | 实证-B |
| COL-005 | `::selection` | 未定义选中高亮（命中 0），沿用站点/浏览器默认蓝。米黄纸面上选中文字是系统蓝块。 | 实证-B |
| COL-058 | 主题档位 | `DEFAULTS` 只有三档 `mi/bai/mo`，**没有「跟随站点」档**；popup 深浅只由 `docdeep_theme==='mo'` 决定（`popup.js:452`），与站点深浅无关。 | 实证-B |

## 八、汇总

- 合计 **61** 条（COL-001 ~ COL-061）。
- 优先级建议：
  1. **COL-001 + COL-003 + COL-052**：主题机制层，用户感知最强烈（深浅混搭、登录页不可读、原生控件色不对）。
  2. **COL-016**：思考块整块未换肤，日常使用每轮必现（截图可见深色横条）。
  3. **COL-060**：墨色主题打印输出不可读，属功能性事故。
  4. **COL-041 ~ COL-048**：弹窗/浮层整族盲区（设置、分享、菜单、tooltip、toast）。
  5. **COL-009 / COL-010 / COL-014 / COL-032**：选择器依赖结构假设，站点改版即静默失效。
- 关联发现（非配色，供参考）：由于 `ds-thinking` 在站点 CSS 中不存在，`THINK_SEL` 实际上只可能命中 `[data-thinking]`；这意味着 `isAssistantStructure()` 的思考流防护分支可能未生效（`docs/known-issues.md` 的 Q-INFLATE-001 正是这一路径）。建议在登录态实测确认 `.ds-think-content` 的元素上是否存在 `data-thinking` 属性。
