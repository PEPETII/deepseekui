## 功能 3：选择性导出（勾选Q + 自包含HTML + 导出模板）

### 功能目标

从全量导出变为可按 Q 勾选部分导出；新增自包含 HTML；MD 增加 front-matter + 代码语言保留。

### 用户场景

100 轮调试会话只想把 Q7 最终方案发同事；把咨询结果导出成可交付 MD/HTML。

### 需求说明

- 大纲/正文每 Q 可勾选（选中集以 `key` 存，不依赖 DOM）；支持全选/清空。
- 导出时仅含选中 Q 及其归属 AI 答 + 小节标题；未选中跳过。
- MD 头部 front-matter：`title/url/exportedAt/schemaVersion`；代码块保留语言标记。
- HTML 为自包含单文件（内联关键样式，图片延后），离线可读。
- 与现有全量导出共存，默认仍全量，新 UI 不打扰老用户。

### 技术方向

- 复用 `qOrder/liveElByKey` 生成勾选源；新增 `SelectionService（Set<key>）`；`buildExport(records, {onlyKeys})` 加过滤分支。
- HTML 先走 `blob` 兜底链路验证，再动 `background.js` 加 `html` mime（避免双链路同时改）。
- 勾选框为注入节点，随 `setOn(false)` 摘除；打印时隐藏。

### 涉及模块

`content.js:buildOutline/collectAllTurns/buildMarkdown/buildExport/fallbackDownload`，`content.css`，`background.js`（Phase-4 才动），`popup.js` 导出入口传参。

### 前置依赖

强依赖功能 5（大纲条目=勾选源）。与功能 4 无硬依赖。

### 当前状态

进行中（Phase-3 MVP 已交付：勾选导MD + front-matter + 代码语言保留；Phase-4 HTML 已交付：自包含单文件）

### 实施阶段

## 功能 5：大纲可用性升级（过滤 + 进度 + 一键补全）

### 功能目标

### 用户场景

50 问只加载 12 问，大纲显示 `12/50`，点补全自动滚一遍补到 50 并回到原位；输入关键字即过滤大纲。

### 需求说明

- 签名需纳入过滤词，避免复用旧列表；`olReg` 保持全量，显示层过滤。

### 用户场景

## 功能 15：对话队列（一次提交多条，逐条自动发送）

### 功能目标

用户一次性提交多条纯文本消息，扩展在**当前会话内**按顺序逐条发出：上一条回答结束后自动发送下一条，直至队列清空，全程无需手动触发。

### 用户场景

把三个待查问题一次贴进「队列」分区，点一次开始；去接杯水回来，三条都已问完，最后一条的回答就在屏幕上。

### 需求说明

- 语义 = **同一会话内连续追问**（用户明确选择），后续每条都能看到前文上下文，不新开会话、不动路由。
- 队列只存内存，只由用户显式启动；刷新或换会话即清空，不落盘。
- 一次性最多 20 条、单条上限 4000 字；只发纯文本，不支持附件、图片、@引用。
- popup「队列」分区负责录题与启停；页面右下角注入面板 `#docdeep-queue` 显示运行进度并可暂停/清空。
- 失败一律暂停并给人话原因（不自动重试）；输入框里有用户草稿时拒绝启动，绝不覆盖。
- 队列运行中拒绝导出与一键补全，反之亦然；切换会话或关闭总闸即中止。

### 技术方向

- `queue.js`：无 DOM / 无 chrome 的纯逻辑层（入队解析 + 发送/停止按钮语义 + reducer 状态机），Node 可单测；`content.js` 只做 DOM 适配（停止语义探针、整条 turn 采样、原生发送原语调用）。
- 结束判定 = 三信号与门：停止语义按钮消失 + 整条 turn 文本静默 + 未超单条看门狗；观察到停止按钮时用短阈值，未观察到时降级为长阈值。**采样取整条 turn 的 `textContent`（含 `.ds-think-content`）**，否则深度思考阶段正文不动会被误判为已完成。
- 新增消息 `DOCDEEP_QUEUE`（popup → content，带回执）与 `DOCDEEP_QUEUE_STATE`（content → popup 广播，节流 500ms）；注入节点 `#docdeep-queue` 挂 `#docdeep-dock`。
- 零新增存储键（队列为内存态，与 `selectedQKeys` 同先例）；不新增权限、host 与网络调用。

### 涉及模块

`queue.js`（新增）、`content.js`、`content.css`、`popup.html`、`popup.js`、`manifest.json`（仅 `content_scripts.js` 与版本号）、`tests/queue.test.js`、`tests/queue-popup.test.js`。

### 前置依赖

强依赖 Phase-6 的发送原语（写回原生 textarea + 派发冒泡 input + 点击原生发送按钮）。该链路的实机验收至今仍欠着，因此队列的第一次真机运行同时承担 Phase-6 的验收职责。

### 当前状态

## 功能 11：左侧会话栏一等布局整合

## 功能 13：原生输入框格式工具栏与富文本表面（Phase-6）

### 功能目标

第一阶段在 DeepSeek 原生消息输入框上方提供 ChatGPT 风格的上下文 Markdown 工具栏，并在 popup【辅助功能】提供持久化开关；后续 WYSIWYG 修订在保留原生 textarea/form/发送按钮节点及归属的前提下，增加本地 contenteditable 编辑表面。用户看到真实行内格式，底层仍同步为 Markdown。

### 需求说明

- 工具栏提供 `B` 加粗、`I` 斜体，以及文本、标题1、标题2、标题3、编号列表、项目符号列表下拉选项。
- 【辅助功能】中的“选区格式工具栏”开关使用 `docdeep_format` 持久化；开启只表示功能启用，不表示工具栏常驻。
- 无选区时不显示、不占用输入框空间；鼠标拖选、Shift+方向键、Ctrl/Cmd+A 形成非空选区时显示。
- 工具栏优先位于选区上方，接近视口边缘时自动调整；选区收缩、输入、失焦、点击页面其他区域、路由切换和扩展关闭时隐藏/清理。
- 支持 Ctrl/Cmd+B、Ctrl/Cmd+I、Ctrl/Cmd+Alt+0/1/2/3。
- 第一阶段操作以原生 textarea 的 `selectionStart/selectionEnd` 为依据；WYSIWYG 修订改用富文本 DOM 到模型的统一文本偏移，最终仍派发冒泡 `input` 同步原生 textarea，并恢复焦点和光标/选区。
- 支持无选区、有选区、多行和中文；重复同类标题/列表/inline 操作可以回退。
- 工具栏为 `.docdeep-injected` 注入节点；扩展关闭、页面路由切换或 textarea 重挂时不遗留工具栏与新增监听。
- 第一阶段不替换/移动/重建 textarea、form、发送按钮，不改 Enter/Shift+Enter、IME、粘贴、附件、草稿、发送协议、fetch、权限或私有 API。

### 技术方向

- `formatMarkdownValue` 作为无 DOM 纯函数处理 inline 与行级 Markdown，并返回替换范围和新的选区。
- `applyMarkdownToTextarea` 优先使用 `textarea.setRangeText(..., 'preserve')`，再派发 `InputEvent('input')`，最后重新聚焦和设置 selection range。
- `classify()` 复用现有异步挂载生命周期；工具栏以 fixed 注入节点按选区所在行的估算几何位置定位，不进入 form 布局，默认 `hidden`。
- 选区监听同时覆盖 textarea 的 `select/keyup/mouseup/click/input/compositionend`、document `selectionchange` 及页面指针点击；点击工具栏按钮/菜单前保存选区，避免暂时失焦丢失。
- 绑定只挂在当前原生 textarea；快捷键在 textarea 局部处理并跳过 `isComposing`/229，既有全局快捷键仍跳过 editable target。
- WYSIWYG 修订新增 `rich-model.js`：用 block + inline marks 表示文本，`content.js` 将 Markdown 解析为 `<strong>/<em>/<s>/<code>` 等本地 DOM，再把编辑表面变化序列化回 textarea；不向 DeepSeek 发送 HTML。
- 富文本操作使用模型范围切分而非 `Range.surroundContents()`；工具栏 `mousedown` 先保存 Selection，格式化后按模型偏移恢复方向、选区和焦点。纯 Enter 在确认原生发送按钮可用后才点击该按钮，否则保留编辑器默认换行；Shift+Enter 不代理。
- WYSIWYG 不引入 Tiptap/ProseMirror/Lexical/CDN；`rich-model.js` 随 MV3 content script 本地打包。该例外会代理可视输入和焦点，原生 textarea 仍留在原 form 中作为同步/发送底层，关闭扩展时恢复其属性。

### 涉及模块

第一阶段涉及 `content.js`、`content.css`、`manifest.json`、`popup.js`、`popup.html`、`docs/工单计划/Phase-6.md` 和原完成报告；WYSIWYG 修订另涉及 `rich-model.js`、`tests/rich-model.test.js`、`docs/工单计划/Phase-6-WYSIWYG.md`、`docs/完成报告/Phase-6-WYSIWYG-完成报告.md` 与 `AGENTS.md`。

## 功能 18：Enter 发送交回站点原生链路（富文本表面）

### 功能目标

修复缺陷：开启「选区格式工具栏」后，在输入框输入文本、按 Enter 不发送（只在编辑区内换行）。做法是不再由扩展猜测「发送按钮」，而是把 Enter 以原生键盘事件转发给原生 `textarea`，交回站点自身的 `onKeyDown` 语义（发送 / 生成中停止 / 空内容提示）。

### 用户场景

用户开启格式工具栏（用 B/I/标题等富文本能力）后，输入完问题按 Enter，期望消息照常发出——这是输入框最基本的行为约定，无论是否开启扩展功能都不应被破坏。

### 需求说明

- Enter 必须始终可用：开启富文本表面后，普通 Enter 发送、Shift+Enter 换行、中文 IME 组合期的 Enter 不误发。
- 不在扩展里复制站点的发送判定：发送 / 生成中停止 / 空内容提示三种结局一律由站点自己决定。
- 不得静默吞键：转发未被站点接管时，回退到原有本地按钮语义；两者都不可用时保留编辑器默认换行（与修复前一致，不制造新缺陷）。

### 技术方向

- `content.parts/04-rich-editor.js` 新增 `forwardEnterToNativeComposer(ta)`：构造 `new KeyboardEvent('keydown', { key: 'Enter', code: 'Enter', bubbles: true, cancelable: true, composed: true })` 并 `ta.dispatchEvent(...)`。React 17+ 的合成事件监听挂在 React 根容器上，事件自 textarea 冒泡即被捕获并派发到其 `onKeyDown`。
- 接管判据：`dispatchEvent` 返回 false **或** `event.defaultPrevented === true`（React 的 `SyntheticEvent.preventDefault()` 会转发到 `nativeEvent`）。任一异常/断连/构造器不可用均返回 false，绝不抛出。
- Enter 分支改为「转发优先 + 回退」：转发成功即 `preventDefault`（阻止 contenteditable 插入换行）；失败则沿用 `nativeComposerSendButton` 点击；再失败则不 `preventDefault`。
- 配套修 `content.parts/03-rich-model.js:syncTextareaFromRich`：写值改走 `HTMLTextAreaElement.prototype` 上的原生 `value` setter。直接 `ta.value = v` 会同步刷新 React 挂在元素实例上的受控值追踪，紧随其后的 `input` 事件被判定为「值未变」而不触发 `onChange`，站点便读不到扩展写入的内容（只转发 Enter 会发出空消息）。

### 涉及模块

`content.parts/04-rich-editor.js`、`content.parts/03-rich-model.js`、`content.parts/00-runtime.js`、`popup.parts/00-core.js`、`popup.html`、`manifest.json`、`AGENTS.md`、`tests/enter-forward.test.js`。

### 前置依赖

站点把 Enter 发送写在原生 `textarea` 自身的 `onKeyDown` 上、且该 textarea 仍归属 React 树（2026-09-15 线上核验，commit `e76f2210`）。依赖比旧的按钮查找**更浅**：不再依赖「composer 有 `form`」与「发送按钮是 `<button>`」——这两条在线上均不成立。
